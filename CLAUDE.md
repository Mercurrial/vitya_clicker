# CLAUDE.md

Этот файл читается в начале каждого чата с Claude Code — на любой машине,
потому что лежит в git. Здесь только то, что нужно знать ДО работы:
как проверять, какие правила нельзя нарушать и почему. Что в игре есть —
в [README.md](README.md) и [docs/DESIGN.md](docs/DESIGN.md).

«ВИТЯ В ДЕЛЕ» — idle-игра на Flutter про друга, который гонит самогон в гараже.
Играют в веб-версию: https://mercurrial.github.io/vitya-v-dele/

## Порядок работы

Работа идёт с нескольких компьютеров. Автопамять Claude на машине не
синхронизируется — общее знание живёт здесь и в коде.

- **Начало:** `git fetch --prune`, посмотреть, нет ли невлитых веток с другой машины
  (`git branch -r --no-merged origin/main`). Есть — сначала влить их, иначе
  новая работа разойдётся со старой. Новую ветку — от свежего `origin/main`.
- **Одна задача — одна ветка — один PR** в `main`. Долгоживущих веток не держим.
- **Решения владельца — в [docs/DECISIONS.md](docs/DECISIONS.md).** Задача
  требует сделать иначе — спросить, а не переделать. Комментарий в коде
  такие решения не защищает: одно уже отменили на другой машине.
- **Конец:** коммит, push, PR. Незапушенное остаётся на одной машине.
- **Влитие в `main` сайт не трогает.** Сайт выкладывается только выпуском
  версии — тегом `vX.Y.Z` (`.github/workflows/deploy-web.yml`, порядок в
  [docs/RELEASE.md](docs/RELEASE.md)). Теги ставит владелец; без его слова
  тег не ставить. PR проверяются анализом, тестами, снимками и сборкой
  веба (`ci.yml`) до влития.
- Упавшую выкладку не перезапускать кнопкой Re-run — только **Run workflow**,
  выбрав тег, а не `main`.

## Проверки

```bash
flutter analyze                                   # должно быть пусто
flutter test                                      # всё зелёное
dart run tools/balance_report.dart 4              # если трогали экономику
```

Если `flutter` не в PATH — см. автопамять своей машины; на основной он в
`D:\Programs\flutter\bin\flutter.bat`, на второй — в
`C:\flutter\bin\flutter.bat`.

- **Flutter 3.24.3**, и CI прибит к нему же. API новее 3.24 не использовать:
  `Color.withValues` уже ломал сборку — нужен `withOpacity`.
- **Снимки экрана (`test/goldens/`) — только через GitHub Actions.** Эталон
  снят на ubuntu, там же его сверяет «Проверка PR». Локально на Windows
  снимки с текстом не совпадут — шрифты рисуются иначе; это ожидаемо, не
  поломка. Локально не переснимать и не коммитить. Переснять:
  `gh workflow run goldens.yml --ref <ветка>` — workflow закоммитит снимки
  в ветку и сам перезапустит проверку; потом `git pull`. Порядок —
  шаг 1 [docs/RELEASE.md](docs/RELEASE.md).
- Переснятые снимки **смотреть глазами** (Read показывает PNG) и сравнивать
  со старыми. Обновлённый не глядя снимок перестаёт что-либо проверять.
- Флакающий тест хуже отсутствующего. Время в тестах — через `timeProvider`
  и `test/support/moments.dart`, а не `DateTime.now()`.
- Полный порядок выпуска версии — [docs/RELEASE.md](docs/RELEASE.md).

## Правила, которые нельзя нарушать

**В сейве только факты.** Сколько куплено и сколько нагнано — хранится.
Доход, цены, мудрость — вычисляются при загрузке. Иначе правка баланса не
дойдёт до тех, кто уже играет.

**До выпуска — пока в `test/fixtures/` нет ни одного `.json`** — версии
баланса и сейва стоят на 1, журнал баланса не пишется, миграций нет:
игроков нет, объяснять правку и переводить сейвы некому. Формат сейва и
числа баланса правятся на месте. Первый эталон снимает выпуск 1.0.0, и два
правила ниже включаются сами — это проверяет `release_contract_test.dart`,
а не чья-то память. Не поднимать версии «на всякий случай»: тест упадёт.

**Миграции сейва заморожены** (`lib/core/save.dart`). Написанный шаг не
правится никогда. Эталоны в `test/fixtures/` не правятся никогда: перестал
читаться — чинить код. Единственное исключение было 25.09.2026 (чистый
старт, [docs/DECISIONS.md](docs/DECISIONS.md)): цепочку v1→v5 и эталоны
тестовых сборок удалили, потому что выпуск их сейвы не читает. Повторять
нельзя.

**Любая правка чисел экономики после выпуска** = поднять `kBalanceVersion`,
запись в `kBalanceLog` человеческим языком, обновить отпечаток в
`test/release_contract_test.dart`. Игроку стало хуже — `isNerf: true` и
компенсация; тест проверяет. Не обходить рассуждением. Числа экономики — не
только `lib/content/balance.dart`, а всё, от чего зависят доход, цены и
скорость: сорта, гости, цели, улучшения, жар и серия, рынок, формулы.
Список — в `test/support/economy_fingerprint.dart`. Новое такое число —
сразу в отпечаток: `economy_fingerprint_test.dart` не пропустит забытое.

**Движок чистый.** `lib/engine/` — функции `состояние → состояние`, без
интерфейса, времени и случайности. Поэтому баланс проверяется симулятором.

**Случайность — из часов, а не из `Random`.** Рынок и гости (`events.dart`) —
чистые функции времени. Им не нужен сейв, они
переживают оффлайн и проверяются тестом.

**Звук и вибрация — только через `Feedback`** (`lib/core/sfx.dart`), и только
внутри действия в `GameNotifier`, а не в кнопке. `HapticFeedback` напрямую не
звать: мимо выключателя в настройках.

**Полосы прогресса — только `FillBar`.** Скопированная вёрстка полос была
сломана во всех пяти местах сразу.

**Графику и звук не скачиваем.** Пиксель-арт — строками в исходнике, иконки —
`tools/make_icons.dart`, баннер — `tools/make_banner.py`, звуки —
`tools/make_sounds.dart`. Правится рецепт, а не двоичный файл.

## Стиль

- Комментарии по-русски и объясняют **почему**, а не что. Если решение
  выросло из поломки — описать поломку: иначе её повторят.
- Коммиты по-русски, повелительным наклонением: «Починить…», «Добавить…».
  В теле — зачем и что пошло не так по дороге.
- Тесты проверяют поведение, а не тексты. На каждую новую механику — свой
  файл в `test/`.
