# Как выпустить версию

Порядок проверен на 1.0.0. Шагов немного, но пропускать нельзя ни один —
каждый закрывает конкретный способ испортить чужой прогресс.

---

## 1. Проверить, что ничего не сломано

```bash
flutter analyze                                   # должно быть пусто
flutter test                                      # все зелёные
flutter test --tags perf --run-skipped            # замеры, на спокойной машине
flutter test --tags golden --run-skipped          # снимки экрана
```

Отдельно посмотреть глазами на снимки в `test/goldens/`. Дважды вёрстка
ломалась так, что ни анализатор, ни тесты этого не видели.

**Если снимок не совпал** — это ещё не поломка. Тест говорит только «экран
стал другим», а не «экран стал хуже». Порядок такой:

1. Открыть `test/failures/*_masked.png` — там подсвечено, что разъехалось.
2. Решить глазами: это то изменение, которое вы делали намеренно?
3. Да — обновить эталон: `flutter test --tags golden --run-skipped --update-goldens`,
   затем **посмотреть на новый снимок** и закоммитить его вместе с правкой.
4. Нет — чинить вёрстку.

Обновлять эталон не глядя нельзя: тогда он перестаёт что-либо стеречь.

## 2. Проверить баланс

```bash
dart run tools/balance_report.dart 4
```

Цели описаны в `lib/sim/balance_targets.dart`, их же стережёт
`test/balance_test.dart`. Отчёт нужен, чтобы посмотреть на кривую целиком,
а не только на «попали/не попали».

## 3. Если менялся баланс

Тест `release_contract_test.dart` не даст забыть, но порядок такой:

1. Поднять `kBalanceVersion` в `lib/content/balance.dart`.
2. Добавить запись в `kBalanceLog`: **что** изменилось и **почему**,
   человеческим языком.
3. Если игроку стало хуже — поставить `isNerf: true` и назначить
   `compensationWisdom`. Молча ронять чужой доход нельзя.
4. Обновить отпечаток в `release_contract_test.dart`.

Игрок увидит этот список при первом запуске новой версии, а компенсация
начислится до показа экрана.

## 4. Поднять версию приложения

В `pubspec.yaml`:

```yaml
version: 1.1.0+2      # +N обязателен: без него Android не поставит обновление
```

## 5. Снять эталонный сейв

```bash
dart run tools/make_fixture.dart 1.1.0
```

Файл ляжет в `test/fixtures/` и **больше никогда не правится**. Это снимок
того, что реально лежит у игроков: каждая следующая версия обязана его
открыть. Проверяется автоматически.

## 6. Записать изменения

`CHANGELOG.md` — для истории. Правки баланса игрок и так увидит в игре,
здесь они остаются на будущее.

## 7. Собрать

```bash
flutter build web --release      # для iPhone и всех остальных
flutter build apk --release      # для Android файлом
```

APK окажется в `build/app/outputs/flutter-apk/app-release.apk`.

## 8. Выложить

```bash
git add -A
git commit -m "Выпустить версию 1.1.0"
git tag v1.1.0
git push origin <ветка> --tags
```

Влить в `main` — и GitHub Actions соберёт и выложит веб-версию сам
(`.github/workflows/deploy-web.yml`). Ссылка всегда одна и та же:

**https://mercurrial.github.io/vitya_clicker/**

Сборка занимает около двух минут, выкладывание — ещё десять секунд.
Раньше этого по ссылке будет старая версия, и это нормально. Ход сборки
виден на вкладке Actions репозитория.

Workflow **не прогоняет тесты** — он только собирает. Поэтому шаг 1 этой
инструкции обязателен: упавший тест здесь никто не поймает, кроме вас.

APK отправляется файлом. Подписан отладочным ключом — **ключ менять
нельзя**, иначе обновление не встанет поверх и придётся удалять игру
вместе с гаражом.

---

## Что нельзя делать никогда

**Менять уже написанную миграцию** в `lib/core/save.dart`. Миграция читает
то, что реально лежит у игрока на диске, а не то, чему равна константа
сегодня. Дублирование кода там намеренное.

**Править файлы в `test/fixtures/`.** Если эталон перестал читаться —
чинить надо код, а не эталон. Это единственное доказательство, что
обновление не потеряет прогресс.

**Класть в сейв производное число.** Доход, цена, мудрость — всё это
считается из фактов при загрузке. Стоит положить туда оценку, и правка
баланса перестанет действовать на тех, кто уже играет. Список запрещённых
ключей стережёт `balance_update_test.dart`.

**Менять ключ подписи APK.** См. выше.

---

## Если что-то пошло не так после выпуска

Сейв игрока никуда не делся: он хранит факты, а не оценки. Почти любую
ошибку баланса можно исправить следующей версией — числа применятся к
старым сохранениям сами, без миграции.

Настоящая беда одна: сломанный формат сейва. От неё защищают эталоны из
`test/fixtures/` и цепочка миграций. Поэтому шаг 5 — не формальность.
